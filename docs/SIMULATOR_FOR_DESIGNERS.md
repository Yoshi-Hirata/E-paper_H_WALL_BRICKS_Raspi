# 演出家チーム向けシミュレーターの使い方

配線ナビの CSV とタイムコードから、ショーの流れ(どの衣装がいつ、どの柄に切り替わるか)を
組み立てて確認するための道具。**インストール不要・ネット不要**、ファイルを 1 個ダブルクリック
するだけで動く。機体(radxa)・基板・DIP・ソケットの知識は要らない。

出来上がった演出は、本番の Conductor(ショー PC)にそのまま渡して使える
([Load bundle…](#6-オペレーターへの渡し方-load-bundle)を参照)。

## 1. 開き方

1. `dist/az27ss-simulator.html` をダブルクリックする
2. ブラウザが開き、シミュレーターの画面が出る。それだけ

- **推奨: Chrome または Edge**。Safari でも動くが、9 章の通り自動保存が効かないことがある
- 最初に開いたときは、サイトから取ってきた配線データ(7 着 + バッグ 3 種)とサンプルの演出が
  最初から入っている(この初期データは開発側が管理する固定セットで、運用 PC の showdata に
  あるファイルが自動で入るわけではない)。何も無い状態から始めたいときは、画面上部の
  **「Start a new (empty) project」** を押す
- ファイルはこの 1 個で完結している(画像も CSS も中に入っている)。メールに添付したり
  USB メモリでやり取りしたりしてよい

## 2. CSV の入れ方

- 配線ナビ(vglabjp.synology.me)から落とした CSV を、画面にそのまま**ドラッグ&ドロップ**するか、
  **「Add CSV…」**で選ぶ(複数選択に対応。対応ブラウザでは、フォルダごとドロップしても
  中の CSV をまとめて拾う)
- ファイル名が全て決める。中身は見ない:
  - `<型番>_map.csv` … 配線図(map)。この型番の「衣装」が 1 つ増える
  - `<型番>_color_<名前>_grid.csv` … 柄(design)。対応する map が無いと
    **「DESIGNS WAITING FOR A MAP」**に並び、map が届き次第つながる
- 同じファイル名で入れ直すと上書きされる(通知が出る)。配線ナビの再エクスポートをそのまま
  入れ直せばよい
- **1 着だけに入れたいとき**は、Designs タブの「DESIGNS OF THIS ITEM」にある
  **「Add CSV」**を使う。選んだ CSV は、別の型番の名前が付いていてもその 1 着の名前で
  保存され、その 1 着だけのものになる(本番の Conductor と同じ動き)
  - ただし、**すでにこのプロジェクトにある別の衣装のマップ CSV(`*_map.csv`)は
    ここでは受け付けない**(配線図は柄と違って入れ替えられるものではない)。
    その場合はファイル名を挙げて断られるので、ヘッダーの「Add CSV」を使う
  - 同じ 1 回の選択で、同じ名前になってしまう 2 つのファイルを選んだときも、
    2 つ目は両方のファイル名を挙げて断られる
- ITEMS タブに衣装ごとのカードが並ぶ。**LOOK 番号**と**型番**はカード上の表示を
  クリックすると編集できる(並び順は LOOK 番号だけで決まる)

### 2.1 配線ナビからデザイン CSV を書き出す手順(2026-09-26)

1. その衣装の配線ナビページ(例: `https://vglabjp.synology.me/look19-wiring/` = AZ271SD1301)を開き、
   **必ず強制再読み込み**する(Safari: Option + Command + R、Chrome: Command + Shift + R)。
   配線は更新されることがあり、古いページのまま書き出すと行数・列数の違う CSV になる
   (シミュレーターの CHECK に「別のレイアウト向けの設計」と出る)。
2. 左の操作列で **配色モード**(パレットのアイコン)に切り替え、色を置く。
3. **「＋ 保存」で配色案として登録**する(未保存だと書き出し時に保存を促される)。
4. 「書き出し・作業ファイル」の **「HW 用 CSV」**を押す → `<型番>_<配色案名>_HW.csv` が
   ダウンロードされる(未指定の鱗があると確認が出る)。このファイルをそのまま
   シミュレーターに入れる(ヘッダーの Add CSV、またはその衣装の DESIGNS OF THIS ITEM の Add CSV)。
5. 「対応表 CSV(初回のみ)」= `<型番>_map.csv` は、初期データに入っているものと同じなので通常は不要。
   配線ナビ側で配線が更新されたと知らされたときだけ入れ直す。

## 3. mm.ss のルール(時刻の入力)

Start・End・ショーの長さなど「いつ」を表す欄は、すべて **`mm.ss`**(分.秒)で入力する。
入力欄には `mm.ss` の印と、今どう解釈されているかの表示(例: `3 min 05 s`)が出るので、
それを見ながら直せばよい。

| 入力 | 意味 |
|---|---|
| `3.05` | 3 分 **05** 秒 |
| `3.5` | 3 分 **05** 秒(秒が 1 桁のときは前に 0 が補われる。`3.05` と同じ。`3.50` ではない) |
| `3:05` | `3.05` と同じ(`:` でも書ける) |
| 秒の部分が `60` 以上 | 赤字になり、直すまで反映されない(例: `3.75` は不可) |

**Refresh(書き換え時間)や遷移の秒数は mm.ss ではなく、ふつうの秒数**(`7.0s` のように末尾に
`s` が付く)。こちらは 60 を超えてよい(遷移の合計時間など)。

## 4. 演出の作り方

### 4.1 柄と遷移(Designs タブ)

- 衣装ごとに、届いている柄(design)を選んで見た目を確認できる(表・裏の切り替えつき)
- **Transition**(遷移)を柄ごとに設定する。6 種類:
  - Socket order(配線の順番そのまま)/ 図心から(Center)/ 上→下 / 下→上 /
    客席から見て左→右 / 右→左
  - 「Socket order」以外を選ぶと、**Span**(その遷移が最初のボードから最後のボードまで
    何秒で終わるか)が出る
  - ここで決めた遷移は、その柄を使うすべてのキューの既定値になる(キュー側で個別に
    上書きすることもできる。4.2 参照)

### 4.2 タイムライン(Timeline タブ)

- 衣装ごとに 1 本の帯(トラック)が並ぶ。**帯の空いているところをクリックすると、
  その衣装の次の柄でキューができる**。ドラッグで動かす(1 秒刻み、Shift を押すと 5 秒刻み)
- キューをクリックすると下に **EDIT CUE** が出る:
  - **Start**(mm.ss) … 指令を送る瞬間
  - **Refresh** … ショー既定の書き換え秒数を使うか、このキューだけ別の秒数にするか
  - **Transition** … この柄の既定の遷移を使うか、このキューだけ別の遷移にするか
  - **Picture complete at …** … Start + Refresh + 遷移の Span から自動計算される、
    絵が完成する時刻(参考表示)
  - **End** … 同じ衣装の次のキューの Start(最後のキューはショーの終わりまで)。
    帯は Start→Complete が斜線、Complete→End が塗りつぶしで表示される
  - 柄と、一部のボードだけ確定していない「途中の柄(partial)」の指定
- **EDIT CUE に「保存」ボタンは無い**。欄を書き換える・カーソルを外すと、その場で反映される
- キューを消すには、キューをクリックして EDIT CUE を開き、**Delete** を押す
- キュー一覧の表(START/COMPLETE/END/ITEM/DESIGN/TRANSITION/STATUS)で全体を見渡せる。
  問題があるキューはここと帯の両方に赤で出る
- **ツールバー**: ショーの長さ(mm.ss)・既定の Refresh 秒数・Save project…/Open project…・
  音楽の選択
- 下段のドックに、全 LOOK のサムネイル(書き換え中のチラつきも再現)・再生/一時停止/停止・
  赤い再生ヘッド(ドラッグでシーク)・シーク先を mm.ss で直接指定する欄がある

### 4.3 音楽

**ショーの音源は、このファイルの中に入っている。** オペレーターから渡された
`az27ss-simulator-YYYYMMDD-with-music.html` には、そのときワークスペースにあったショーの
音源がそのまま埋め込まれている。ダブルクリックして再生を押せば、**何も選ばずにそのまま鳴る**。

- ツールバーの音楽欄に、埋め込まれている曲名が **「曲名 · built in」** と出る
- **音源が差し替わったときは、新しいファイルが届く**。演出家側で音源を入れ替える操作は無い
  (オペレーター側の手順は [CONDUCTOR_START.md](CONDUCTOR_START.md) 5 章)。
  届いたファイルのツールバーで曲名を見れば、どの音源が入っているかはすぐ分かる
- 別の音源で確かめたいときは **Pick another file…** で自分のパソコンの音楽ファイルを選べる。
  これは**そのセッションの間だけ**で、**Back to the built-in track** で埋め込みの音源に戻る
- 自分で選んだ音源は、名前だけがプロジェクトに記録される(音のデータは入らない。8 章参照)。
  プロジェクトを開き直すと埋め込みの音源に戻り、
  「(re-pick the file…) · Playing the built-in track 曲名 instead」と、
  **記録されている名前**と**実際に鳴っているもの**の両方が出る

> 音源を含まない版(`az27ss-simulator.html`)を受け取った場合は、上の「built in」の表示が無く、
> **Pick file…** で毎回自分で音源を選ぶことになる。音が鳴らないときは、まずここを見ること。

## 5. プロジェクトの保存と再開

- ブラウザを閉じても、直前の状態が**自動的にこのブラウザに**保存される(0.8 秒ごと)。
  次に同じファイルを同じブラウザで開けば続きから始まる
- 別のパソコンに移す、他の人に送る、確実にバックアップを取りたいときは、Timeline
  ツールバーの **Save project…** でファイル(`az27ss-YYYYMMDD-HHMM.json`)に書き出す。
  **Open project…** で読み込む(このシミュレーターで作ったプロジェクトのファイルなら、
  6 章の bundle でも、CSV を含まない単純なショーファイルでもどちらも読み込める)
- 自動保存の制限は 8 章を参照

## 6. オペレーターへの渡し方(Load bundle…)

演出が固まったら、Timeline の **Save project…** で書き出したファイルを、そのまま
ショー PC の Conductor に渡す。

1. できたファイル(`az27ss-YYYYMMDD-HHMM.json`)をメールや USB メモリでショー PC へ
2. Conductor の Timeline タブ、**「Load show…」の隣にある「Load bundle…」**でそのファイルを選ぶ。
   ファイルの版が新しすぎるときはここで断られる(確認ダイアログは出ない)
3. 確認ダイアログ(「同名の CSV は上書きされ、Undo では戻らない」という趣旨の注意つき)が
   出るので内容を確認して OK。すると:
   - シミュレーターで入れた CSV が、ショー PC のワークスペースに追加される。**同名のファイルは
     上書きされ、これは Undo で元に戻らない**(トーストに上書きされた数が出る)
   - ファイル名が使えない CSV(パスが混ざっている等)だけは追加されず、理由がトーストに出る
   - **タイムライン(キュー・遷移・LOOK 番号・型番)が、シミュレーターで作ったものに置き換わる。
     ショー PC 側にだけあった項目(bundle に出てこない衣装のラベルや遷移設定)は消える**
     ―― シミュレーターの内容がそのまま新しいタイムラインになる、と考えればよい
   - **ショー PC 側の機体(radxa)の割り当てと、基板番号の書き換え(duplicate 等で使う
     ボード番号の付け替え)はどちらもそのまま残る**(シミュレーターにはどちらの概念も無いため)
   - **音楽はファイル名だけが記録され、音のデータそのものは入っていない**。ショー PC 側で
     もう一度その音楽ファイルを選び直す必要がある(8 章と同じ制限。黄色い帯で知らせる)
   - 結果(追加された CSV の数、上書きされた数、キュー数、警告)がトーストで出る
4. 元に戻したいときは Conductor の Undo(タイムラインの取り込みは 1 回の Undo で戻る。
   **CSV の追加・上書きは Undo の対象外**なので、ファイル自体は残る)

逆に、ショー PC 側の演出をシミュレーターに持ってきて続きを直すこともできる。Conductor の
**Save show…** で書き出したファイルを、シミュレーターの **Open project…** で読み込めばよい
(この場合はタイムラインだけが入り、CSV はシミュレーター側に既にあるものを使う)。

## 7. バリデーション(確認事項)は本番の画面と同じ

「同じ衣装が二重に書き換わっていないか」「同じルックの Tops と Skirt が同時に
書き換わっていないか」といったチェックは、ショー PC の画面と全く同じ計算をしている。
機体を割り当てていない衣装は、画面の表示上は仮の名前(LOOK 番号)に読み替えられる
だけで、判定そのものは変わらない。

**ただし 1 つだけ、シミュレーターでは絶対に出せないチェックがある**: 「2 着が同じ radxa に
乗っていて、書き換えの間隔が詰まりすぎている(最短間隔・重なりの警告)」は、どの衣装を
どの機体に乗せるかが決まって初めて計算できるので、機体という概念が無いシミュレーター側
では判定しようがない。これはショー PC で Load bundle… したあと、機体を割り当てた状態で
初めて確認できる。

## 8. 制限

- **プロジェクトのファイルに音は入らない**: プロジェクトのファイル(Save project… /
  Load bundle…)には音楽ファイルの**名前だけ**が入り、音のデータ自体は入らない。
  ショーの音源はシミュレーター本体(`...-with-music.html`)の側に埋め込まれているので、
  開き直しても鳴る ―― 自分で **Pick another file…** で選んだ音源だけは、開き直すと
  埋め込みの音源に戻る(4.3 章)
- **自動保存はブラウザごと**: 同じパソコンでも、別のブラウザ(Chrome と Edge など)や
  シークレット/プライベートウィンドウでは別の保存先になる。**大事な演出は Save project…
  で必ずファイルに書き出しておく**こと
- **Safari では自動保存が効かないことがある**: Safari の設定によっては、ファイルを
  ダブルクリックして開いた HTML(`file://`)からの保存が拒否される。この場合も
  シミュレーター自体は普通に使えるが、閉じると状態が消えるので、こまめに
  **Save project…** すること
- 保存されるデータが 4 MB を超えると自動保存は諦める(トーストで 1 回だけ知らせる)。
  CSV や演出の量が普通のショーであればまず超えない

## 9. 自己テストの使い方

シミュレーター自身が壊れていないか(Python 版の計算と同じ答えを返しているか)を、
その場で確認できる。

- 画面の **Help タブ**にある **「Run self-test」**ボタンを押す
- または、アドレスバーで開いているファイルの末尾に `#selftest` を付けて開き直す
  (例: `dist/az27ss-simulator.html#selftest`)。開いた瞬間に自動で走る
- 結果は「◯件中◯件成功」の形で出る。**失敗が 1 件でもあれば、演出の計算(遷移の順番や
  タイムラインの判定)を信用せず開発チームに連絡する**こと
